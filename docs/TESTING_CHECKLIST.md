# Полный регламент и чеклист комплексного тестирования NMSimToolkit

Данный документ представляет собой единый исчерпывающий чеклист верификации и тестирования программного комплекса **NMSimToolkit** — от изоляции расчетного ядра (`core/`) до сквозных сценариев взаимодействия с графическим интерфейсом (`gui/`).

---

## Стандарты окружения и выполнения тестов

* **Изоляция:** Запуск тестов производится **строго внутри виртуального окружения Python `venv`** (`.venv` в корне проекта).
* **Интерпретатор для тестов:** `.venv\Scripts\python.exe -m unittest discover tests` или `.venv\Scripts\pytest.exe`.
* **Headless/Offscreen режим:** Тестирование GUI в автоматизированном режиме выполняется с флагом платформы `-platform offscreen` для предотвращения всплывания окон и обеспечения работы в CI/фоновых агентах.
* **Потоковая изоляция:** Перед запуском тестов переменные многопоточности научных библиотек фиксируются в значение `1`:
  * `OMP_NUM_THREADS=1`
  * `MKL_NUM_THREADS=1`
  * `NUMEXPR_NUM_THREADS=1`

## Уровень 1. Расчетное ядро (`core/`) и слой конфигурации (`core/config/`)

### 1.1. Геометрия (`core/geometry/`)
- [ ] **1.1.1. Геометрические примитивы:**
  - [ ] Корректность объемов: `Box`, `Cylinder`, `Sphere`, `Tube`, `VoxelVolume`, `WoodcockVolume`.
  - [ ] LBYL-проверка инвариантов: генерация `ValueError` при нулевых или отрицательных габаритах ($size \le 0$, $radius \le 0$).
  - [ ] Вычисление `local_bound` строго у классов `Volume`, отсутствие свойства у `SpatialNode`.
- [ ] **1.1.2. Матрицы и компиляция:**
  - [ ] Корректный пересчет мировой матрицы трансформации `world_matrix` при изменении локальной матрицы `local_matrix` родителя.
  - [ ] Компиляция сцены в непрерывные буферы ядра через `GeometryCompiler`.

### 1.2. Материалы и физические процессы (`core/materials/`, `core/physics/`)
- [ ] **1.2.1. База материалов:**
  - [ ] Доступность стандартных материалов (`material_database`: Air, Water, Lead, NaI, BGO, LSO и др.).
  - [ ] Расчет эффективного атомного номера, плотности и электронной плотности.
- [ ] **1.2.2. Физические процессы:**
  - [ ] Верификация сечений взаимодействия фотонов (Compton, Photoelectric, Rayleigh/Coherent).
  - [ ] Отсутствие скрытых дефолтов при интерполяции сечений: строгая ошибка при выходе за пределы энергетического диапазона.
  - [ ] Буферы физических взаимодействий (`DeadParticlesBuffer`, `PhysicsBuffer`, `InteractionBuffers`).

### 1.3. Источники частиц (`core/source/`)
- [ ] **1.3.1. Генерация частиц:**
  - [ ] Точечный источник (`PointSource`), изотропное распределение направлений импульса.
  - [ ] Объемные и воксельные источники (`VoxelizedSource`).
- [ ] **1.3.2. Расчет временного шага:**
  - [ ] Корректный расчет шага по времени $dt = N / A$ с учетом единиц системы измерения (`* units.Bq`).
  - [ ] Исключение размерностных ошибок (шаг $dt$ должен составлять порядка микросекунд для реалистичных активностей, а не фемтосекунд).

### 1.4. Транспорт частиц (`core/transport/`)
- [ ] **1.4.1. Алгоритмы трекинга:**
  - [ ] Трассировка с явным пересечением границ и Woodcock delta-tracking в гетерогенных средах.
  - [ ] Завершение трекинга при выходе за пределы внешнего мира (`World Volume`) или поглощении.
- [ ] **1.4.2. Жизненный цикл SimulationManager:**
  - [ ] Безопасная инициализация во вторичных потоках (без конфликта с `signal.signal` в неглавном потоке).
  - [ ] Корректная остановка симуляции по исчерпанию лимита частиц или времени без дедлока потоков.

### 1.5. Конфигурация и сериализация (`core/config/`)
- [ ] **1.5.1. Загрузка и валидация YAML:**
  - [ ] Десериализация файлов сценариев (`yaml_loader.load_simulation_config`) в строгие Pydantic-модели `SimulationConfig`.
  - [ ] Строгая реакция на синтаксические ошибки, неизвестные типы объемов или незакрытые интерполяционные переменные (`${...}`).
- [ ] **1.5.2. Построение сцены (`SceneBuilder`):**
  - [ ] Построение иерархии узлов ядра по конфигурации YAML (`build_scene`).
  - [ ] Разрешение размерностей через `pint` / `hepunits`.
- [ ] **1.5.3. Экспорт конфигурации (Round-Trip тест):**
  - [ ] Загрузка YAML $\rightarrow$ сборка сцены $\rightarrow$ экспорт сцены через `export_to_config` $\rightarrow$ повторная загрузка.
  - [ ] Полная идентичность параметров и топологии графа сцены до и после сериализации.

## Уровень 6. Сквозные End-to-End сценарии (E2E)

- [ ] **E2E-1: Сквозной поток расчета «с чистого листа»:**
  1. Запуск окна приложения в тестовом цикле Qt.
  2. Добавление фантома (`Volume` Box) через контекстное меню дерева сцены.
  3. Назначение материала "Water" и габаритов в инспекторе свойств.
  4. Добавление точечного источника излучения и детектора `GammaCamera`.
  5. Нажатие `Run` $\rightarrow$ проверка генерации треков в 3D вьюпорте $\rightarrow$ проверка прироста отсчетов в `ResultsViewer` $\rightarrow$ проверка формирования энергетического пика в спектре.
  6. Нажатие `Pause` $\rightarrow$ подтверждение остановки накопления счета.
  7. Нажатие `Resume` $\rightarrow$ подтверждение возобновления счета.
  8. Нажатие `Stop` $\rightarrow$ корректный перевод всех компонентов в исходное состояние.
- [ ] **E2E-2: Загрузка конфигурации и проведение симуляции:**
  1. Вызов `File -> Open` и загрузка эталонного файла конфигурации `nema_1_cam.yaml`.
  2. Проверка соответствия структуры в `SceneTreeWidget` и геометрических акторов в `VTKViewport`.
  3. Проверка расчетного временного шага ($dt \approx 10$ мкс).
  4. Запуск расчета и верификация накопления счета в матрице детектора.
- [ ] **E2E-3: Интерактивная модификация сцены на паузе:**
  1. Старт симуляции $\rightarrow$ пауза.
  2. Выбор узла камеры в дереве сцены.
  3. Изменение угла ориентации камеры в `PropertyInspector`.
  4. Проверка автоматического обновления матрицы во ViewModel и перемещения актора камеры во вьюпорте.
  5. Возобновление расчета $\rightarrow$ регистрация частиц в новом геометрическом положении.
- [ ] **E2E-4: Очистка и сброс сцены:**
  1. Вызов действия `File -> New Scene`.
  2. Проверка полного удаления акторов из `VTKViewport`, очистки гистограммы и матрицы в `ResultsViewer`, сброса дерева до пустого корневого узла.

## Уровень 7. Надежность, безопасность ресурсов и стресс-тесты

- [ ] **7.1. Контроль утечек памяти (Memory Leaks Audit):**
  - [ ] Замер количества объектов `gc.get_objects()` до и после 100 циклов добавления и удаления акторов в `VTKViewport`.
  - [ ] Отсутствие циклических ссылок между Qt-виджетами и ViewModel при закрытии док-панелей.
- [ ] **7.2. Экстренное завершение симуляции:**
  - [ ] Принудительное закрытие `MainWindow` (`win.close()`) во время активного цикла вычислений.
  - [ ] Проверка: все дочерние процессы завершены (`len(multiprocessing.active_children()) == 0`).
  - [ ] Проверка: все разделяемые буферы памяти корректно освобождены (`shm.unlink()`), системные дескрипторы не зависают.
- [ ] **7.3. Устойчивость к некорректным данным (Fail-Fast & LBYL):**
  - [ ] Попытка открыть поврежденный или неполный YAML-файл: показ диалога с понятным описанием ошибки, приложение не падает.
  - [ ] Попытка ввести некорректные символы или отрицательные значения в инспекторе свойств: фильтрация валидатором.
- [ ] **7.4. Высоконагруженный поток IPC:**
  - [ ] Генерация потока $>10^5$ треков/сек в `multiprocessing.Queue`.
  - [ ] Проверка стабильности GUI: интерфейс сохраняет отзывчивость, буфер треков не переполняет оперативную память.
