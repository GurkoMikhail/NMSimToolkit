# План архитектурного рефакторинга GUI NMSimToolkit (Модуляризация)

Этот документ описывает план рефакторинга графического интерфейса NMSimToolkit для обеспечения модульности, гибкого конфигурирования через графы (Procedures, Data Handlers) и интеграции параллельных вычислений через Оркестратор.

## Утвержденные архитектурные решения

1. **Жизненный цикл симуляции:** GUI будет делегировать создание пула задач классу `Orchestrator`, а `SimulationSession` (теперь `OrchestratorSession`) станет диспетчером задач.
2. **Ограничение стриминга (IPC) для параллельных процессов:** Тяжелый IPC-стриминг (треки частиц, 3D карты доз, спектры) будет подключаться исключительно к одному **активному (выделенному в UI) процессу**. Остальные процессы пишут данные напрямую в HDF5 и рапортуют только легковесную телеметрию (статус, прогресс, CPS) через общую очередь. Это критически важно для производительности.
3. **Размещение в UI:** Списки Процедур и Обработчиков Данных будут вынесены в отдельные независимые док-виджеты (`QDockWidget`), что позволит свободно перемещать их по экрану (например, располагать рядом с `Иерархией сцены` или в любых других док-областях).
4. **Визуализация DataHandlers:** Вместо сложного древовидного представления (TreeView) для обработчиков данных будет использован плоский список (`QListWidget` / `QListView`), так как обработчики не имеют строгой иерархии (в отличие от узлов сцены).
5. **Синхронизация Процедуры и Сцены:** Обязательная жесткая синхронизация свойств (таких как число гамма-камер) со `SceneGraph`.
   * *Архитектурное примечание:* В текущей итерации реализуется подход, где Процедура выступает "ведущей" и принудительно задает количество камер в сцене. В дальнейшем может быть реализован инвертированный подход, где Процедура является лишь аспектом геометрии, считывает параметры из графа сцены и подстраивается под них. Этот вопрос оставлен на будущее, но синхронизация будет работать.

## Пошаговый план реализации

### 1. Модуль Процедур (Procedures)

Выделение настроек протоколов (SPECT, PET, CustomSweep) в полноценные ViewModel-сущности, редактируемые через `PropertyInspector`.

#### `gui/viewmodels/procedure_viewmodel.py`
- Создание базового `BaseProcedureViewModel`.
- Реализация `SpectProcedureViewModel` со свойствами `views`, `gamma_cameras`, `radius`, `time_per_view`.
- Реализация реактивной логики синхронизации со `SceneViewModel` (обязательное обновление `GammaCameraViewModel` при изменении параметров процедуры).

#### `gui/views/procedure_selector_widget.py`
- Новый класс-обертка на базе `QDockWidget`.
- Содержит виджет выбора типа исследования (ОФЭКТ, ПЭТ, Пользовательский скан).
- Выбранный элемент автоматически привязывается к `PropertyInspector` для детальной настройки параметров.

#### Удаление `gui/views/simulation_settings_dialog.py`
- Устаревшее монолитное диалоговое окно подлежит удалению. Настройки прозрачно распределяются между Процедурами и Обработчиками данных.

---

### 2. Список Обработчиков Данных (DataHandler List)

Визуальное управление конфигурацией `DataManagerConfig` и его списками `handlers` в виде плоского списка.

#### `gui/viewmodels/data_handler_viewmodel.py`
- Создание ViewModel-классов, отражающих `AnyDataHandlerConfig` (например, `HistoryAssemblerHandlerViewModel`, `SensitiveVolumeHandlerViewModel`, `DoseMapHandlerViewModel`, `DirectStreamHandlerViewModel`).
- Выставление свойств для `PropertyInspector`: списки `sensitive_volumes`, флаги `save_initial_states` и т.д.

#### `gui/views/data_handler_list_widget.py`
- Класс на базе `QDockWidget` с встроенным `QListWidget` или `QListView` (отказ от Tree-вида в пользу плоского списка).
- Поддерживает добавление/удаление обработчиков данных через контекстное меню.
- Интегрирован с общим `PropertyInspector` (выбор хэндлера открывает его свойства).

---

### 3. Параллельная Оркестрация (Simulation Jobs)

Интеграция GUI с `core.config.orchestrator` для генерации и управления множественными процессами.

#### `gui/controllers/orchestrator_session.py`
- Новый контроллер, выступающий диспетчером для пула задач.
- Метод `generate_jobs()` использует текущий протокол из `ProcedureViewModel` и генерирует плоский список конфигураций задач (через `CustomSweepProtocolConfig`).
- Реализация легковесной IPC очереди (через `multiprocessing.Manager().Queue()`) для сбора базовой статистики (прогресс, CPS) со всех запущенных воркеров.
- Реализация механизма "Фокуса": передача `shm_name` (для тяжелого трейсинга) только одному конкретному "сфокусированному" воркеру при старте пула.

#### Упрощение `gui/controllers/simulation_session.py`
- Класс станет просто оберткой над единичным потоком/IPC (один Job). Он больше не будет отвечать за цикл `views_number` и смену геометрии гамма-камер — это переходит в зону ответственности Оркестратора.

#### `gui/views/simulation_jobs_widget.py`
- Док-панель (`QDockWidget`) со списком/таблицей сгенерированных процессов (например, 20 ракурсов ОФЭКТ или пользовательский скан).
- Отображение статуса (Ожидание, Выполняется, Завершено) и индикатора прогресса для каждого процесса в списке.
- Возможность "Предпросмотра" задачи (обновление 3D-вьюпорта параметрами конкретной задачи без запуска самой симуляции).
- Выделение в списке одного процесса означает, что именно к нему будет подключена "Глубокая инспекция" (3D трейсы, спектры, дозы).

#### Изменения в `core/config/orchestrator.py`
- Адаптация метода `_worker_function` для корректного внедрения динамических `GuiStreamDataHandler`. Если процесс выбран для инспекции, он получит нужный `shm_name` через словарь задачи.
- Добавление канала обратной связи для статусов выполнения (Progress/CPS).

---

### 4. Рефакторинг MainWindow

#### `gui/views/main_window.py`
- Регистрация трех новых док-панелей: `Процедуры`, `Обработчики Данных`, `Задачи симуляции`.
- Разрешение на свободное перемещение док-панелей (`Qt.LeftDockWidgetArea`, `Qt.RightDockWidgetArea` и др.).
- Интеграция `OrchestratorSession`.
- Связывание кнопок панели инструментов ("Запуск/Пауза") с новым диспетчером задач вместо устаревшего `SimulationSession`.
