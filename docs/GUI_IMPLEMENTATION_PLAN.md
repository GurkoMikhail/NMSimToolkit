# План реализации: Интерактивный 3D GUI для NMSimToolkit (PySide6 + PyVista)

Данный документ представляет собой архитектурную спецификацию и пошаговый план разработки графического интерфейса для пакета моделирования ядерной медицины **NMSimToolkit**, включая 3D визуализацию со специализированными манипуляторами (ОФЭКТ/ПЭТ), поддержку DICOM-палитр для фантомов, изоляцию ядра через паттерн MVVM и дескрипторы полей, межпроцессную телеметрию (IPC) и подготовку устанавливаемого pip-пакета.

---

## Ключевые архитектурные решения

1. **Специализированные манипуляторы (ОФЭКТ/ПЭТ):** Вместо общего 6-DOF Gizmo реализуются процедурно-ориентированные манипуляторы (ОФЭКТ — радиус орбиты $R$, угол $\theta$; ПЭТ — геометрия кольца). Это исключает геометрические коллизии и некорректные положения детектора.
2. **LOD Volume Rendering с DICOM-палитрами:** Рендеринг воксельных фантомов на базе `vtkSmartVolumeMapper` с адаптивным шагом трассировки лучей (LOD) и поддержкой DICOM-палитр (Hot Iron, Rainbow, GE Color, NIH, PET 20 Step).
3. **Строгий MVVM и изоляция ядра (Core Isolation):** Вычислительное ядро (`core/`) остается полностью независимым от событийной модели UI. Паттерн *Observer* и реактивность реализуются исключительно в слое GUI через *ViewModels* и *дескрипторы полей* (`@observable_field`). Ядро не содержит логики событий и сигналов, что гарантирует безопасность сериализации (Pickling) для многопроцессности.
4. **Многопроцессность и IPC-Телеметрия:** Для обмена данными между вычислительными процессами (воркерами `multiprocessing.Pool`) и потоком GUI используются механизмы IPC:
   - `multiprocessing.Queue` для небольших пакетов 3D-треков.
   - `multiprocessing.shared_memory` (SharedMemory) для матриц 2D-проекций без оверхеда на сериализацию.
   - Поддержка режима **SWMR (Single Writer Multiple Reader)** в `h5py` для бесконфликтного чтения промежуточных результатов.
5. **Безопасность мультипроцессинга на Windows:** Защита точки входа `if __name__ == '__main__':` и вызов `multiprocessing.freeze_support()` в точке входа GUI для предотвращения рекурсивного открытия окон.
6. **Формат поставки:** Стандартный устанавливаемый pip-пакет на базе `pyproject.toml` с точками входа `nmsim-cli` и `nmsim-gui`.

## Декомпозиция изменений по подсистемам

### 1. Доработка ядра (Headless Core Layer)

*В ядре **полностью отсутствует** логика UI, сигналов или Qt. Ядро остается чистым и сериализуемым.*
* **`core/transport/simulation_managers.py` [MODIFY]:** Введение состояний (`IDLE`, `RUNNING`, `PAUSED`, `STOPPED`). Кооперативная остановка и пауза через `threading.Event` (`_stop_event`, `_pause_event`). Метод пошагового выполнения `step_once()` для покадрового анализа треков.
* **`core/data/stream_handlers.py` [NEW]:** Класс `GuiStreamDataHandler(BaseDataHandler)`: запись треков в `multiprocessing.Queue` и запись проекций детектора в кольцевые буферы `multiprocessing.shared_memory.SharedMemory`.
* **`core/data/data_manager.py` [MODIFY]:** Активация флага `libver='latest'` и `swmr=True` в `h5py.File`, чтобы GUI мог безопасно читать файл во время записи воркерами.
* **`core/config/exporter.py` [NEW]:** Класс `SceneExporter`: обратная сериализация чистого графа сцены (`Volume`, `SpatialNode`) в Pydantic-конфигурации `SimulationConfig` и сохранение в YAML.

---

### 2. Подсистема ViewModels и Реактивность (MVVM Layer в GUI)

*Обеспечивает реактивность и двустороннее связывание данных между ядром, инспектором свойств и 3D-вьюпортом.*
* **`gui/viewmodels/decorators.py` [NEW]:** Класс-дескриптор `observable_field`. Перехватывает установку атрибутов, обновляет значение в объекте ядра (`core_node`) и уведомляет подписчиков (через сигнал или событие ViewModel).
* **`gui/viewmodels/node_viewmodel.py` [NEW]:** Базовый класс `NodeViewModel(QObject)`. Предоставляет сигнал `property_changed(str, object)`. Использует дескрипторы для реактивных свойств (`name`, `local_matrix`, `size` и т.д.).
* **`gui/viewmodels/scene_viewmodel.py` [NEW]:** Главная модель сцены (`SceneViewModel`), управляющая иерархией `NodeViewModel`. Обеспечивает добавление, удаление и поиск узлов без вмешательства в структуру классов ядра.

---

### 3. Подсистема 3D Вьюпорта и Палитр (PyVista / VTK Layer)

* **`gui/viewport_3d/dicom_colormaps.py` [NEW]:** Модуль палитр ядерной медицины (Hot Iron, Rainbow, GE Color, NIH, PET 20 Step) с возможностью импорта сторонних LUT-файлов и конвертацией в `vtkColorTransferFunction` / `vtkPiecewiseFunction`.
* **`gui/viewport_3d/vtk_viewport.py` [NEW]:** Обертка над `pyvistaqt.QtInteractor`. Инициализация камеры, координатной сетки, источника света и обработчиков событий мыши.
* **`gui/viewport_3d/voxel_volume_renderer.py` [NEW]:** Рендерер для `WoodcockVoxelVolume`. Использование `vtkSmartVolumeMapper` с адаптивным LOD: увеличенный шаг трассировки (`sample_distance`) при интерактивном вращении/панорамировании и переход к честному воксельному разрешению в статике.
* **`gui/viewport_3d/spect_manipulator.py` [NEW]:** Манипулятор траектории ОФЭКТ с ограничением по степеням свободы (радиус коллиматора $R$, угол поворота гантри $\theta$).
* **`gui/viewport_3d/pet_manipulator.py` [NEW]:** Манипулятор геометрии ПЭТ-сканера (диаметр кольца, аксиальная длина).
* **`gui/viewport_3d/track_renderer.py` [NEW]:** Отрисовка 3D-треков фотонов (`vtkPolyData`) с цветовой дифференциацией физических взаимодействий (Compton, Photoelectric, Rayleigh, Detection).

---

### 4. Пользовательский интерфейс (PySide6 UI Layer)

* **`gui/views/main_window.py` [NEW]:** Главное окно на базе `QMainWindow` с поддержкой док-панелей (`QDockWidget`), панелью инструментов и меню.
* **`gui/views/scene_tree_widget.py` [NEW]:** Иерархическое дерево сцены на `QTreeView`, связанное с `SceneViewModel`.
* **`gui/views/property_inspector.py` [NEW]:** Инспектор параметров выбранного узла (координаты, материалы, физические размеры, радиоактивность, выбор палитры фантома).
* **`gui/views/results_viewer.py` [NEW]:** Панель визуализации результатов на базе `pyqtgraph` (накопленные 2D-проекции, гистограммы энерговыделения, профили распределения счетов).

---

### 5. Контроллеры исполнения и IPC (Controllers Layer)

* **`gui/controllers/simulation_runner.py` [NEW]:** Поток управления симуляцией на базе `QThread`. Изолирует запуск `Orchestrator` или одиночных экземпляров `SimulationManager`.
* **`gui/controllers/ipc_receiver.py` [NEW]:** Поток/таймер опроса `multiprocessing.Queue` и чтения `SharedMemory` с генерацией Qt-сигналов для обновления 3D-сцены и 2D-проекций без блокировки графического интерфейса.

---

### 6. Пакетирование и установка (Packaging Layer)

* **`pyproject.toml` [NEW]:** Конфигурационный файл пакета по стандартам PEP 517/621.
  - Зависимости: `pyside6`, `pyvista`, `pyvistaqt`, `pyqtgraph`, `numba`, `numpy`, `scipy`, `h5py`, `hepunits`, `pydantic`, `pyyaml`.
  - Точки входа (Console & GUI scripts):
    ```toml
    [project.scripts]
    nmsim-cli = "run_simulation:main"
    nmsim-gui = "gui.app:main"
    ```
* **`gui/app.py` [NEW]:** Точка входа GUI с обязательным вызовом `multiprocessing.freeze_support()`, установкой темной темы и запуском главного цикла событий Qt.

## План верификации

### Автоматизированные тесты
1. `pytest tests/test_viewmodels.py` — проверка работы дескрипторов `observable_field`, корректности трансляции значений в ядро и генерации сигналов.
2. `pytest tests/test_ipc_telemetry.py` — стресс-тест передачи пакетов треков через `multiprocessing.Queue` и матриц через `SharedMemory`.
3. `pytest tests/test_hdf5_swmr.py` — проверка параллельного чтения HDF5 в режиме SWMR во время активной записи.
4. `pytest tests/test_scene_exporter.py` — экспорт сконфигурированной в GUI сцены в YAML и валидация схемы.
5. `pytest tests/test_dicom_colormaps.py` — корректность парсинга LUT и генерации структур VTK.
6. `pip install -e .` и запуск команд `nmsim-cli --help` / `nmsim-gui --help`.

### Ручная валидация
1. **Реактивность MVVM:** Проверка синхронного обновления: изменение параметров в инспекторе меняет 3D-вид, движение манипулятора в 3D меняет значения в полях инспектора.
2. **Многопроцессный запуск на Windows:** Запуск моделирования из GUI с пулом воркеров — отсутствие паразитных окон и утечек дескрипторов.
3. **LOD Volume Rendering:** Плавное вращение объемного воксельного фантома (>30 FPS в динамике) с возвратом детализации в статике.
4. **Телеметрия в реальном времени:** Появление треков и обновление матрицы детектора в UI без подвисания интерфейса.
